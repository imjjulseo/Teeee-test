# 0. 한눈에 보는 게임 정의

**장르:** 실시간 그리드 퍼즐 / 위치 교환형 퍼즐 / 제한시간 스코어어택

**핵심 목표:** 제한시간(기본 60초) 동안 플레이어 블록을 이동시키며 주변 4칸의 색을 동일하게 만들어 블록을 제거하고, 화면 위 **족보**의 색 순서대로 제거해 족보를 완성하여 최대한 많은 점수를 획득한다.

**핵심 조작:** 1회 입력(방향키 / 스와이프 / 가상 방향키) = 상하좌우 1칸 이동. 목적지에 색 블록이 있으면 플레이어 블록과 해당 블록의 위치를 교환한다.

**핵심 판정:** 이동이 완료된 뒤(이동 애니메이션 종료 후) 플레이어 블록의 상·하·좌·우 네 칸이 모두 존재하고, 네 블록의 색이 같으면 해당 4블록을 제거한다. 제거 자체는 0점이며, 제거한 색이 족보를 진행시켜 족보를 완성하면 점수를 얻는다.

> **Core Loop**
>
> 판 읽기 → 목표 색/경로 결정 → 플레이어 이동 및 블록 교환 → 플레이어 주변 4방향 정렬 → 4블록 제거(+2.5초) → 족보 진행·완성 시 득점 → 남은 시간 동안 반복

## 현재 규칙에서 바로 드러나는 설계 특징

- 플레이어 자신은 “커서”가 아니라 실제 보드 위 한 칸을 차지하는 ‘오브젝트’이며, 이동할 때 색 블록의 위치까지 바꾼다.

- 매치 판정의 중심은 항상 플레이어 위치다. 일반적인 3-match처럼 보드 전체를 탐색하는 구조가 아니다.

- 랜덤 초기 배치이지만 네 색의 개수는 동일하므로 완전 무작위보다 분포가 통제된다.

- 제한시간이 있으므로 퍼즐 해답의 존재보다 빠른 판단·경로 최적화·입력 숙련이 점수에 직접 영향을 준다.

- 제거된 칸은 일정 시간 뒤 새 블록으로 다시 자라며(지연 리필), 시간이 지날수록 시간이 줄어드는 속도와 리필 속도가 빨라진다(시간 가속).

# 2. 보드와 오브젝트 명세

## 2.1 좌표와 보드 크기

**권장 표기:** 보드 한 변의 칸 수를 N이라 하고 보드는 N×N으로 정의한다. 플레이어가 정확히 중앙에서 시작하려면 N은 홀수여야 한다. 좌표는 0 기반 (x, y)이다.

**색 블록 개수:** 플레이어가 1칸을 차지하므로 색 블록 총수는 N²-1, 색상별 개수는 (N²-1)/4이다.

| **예시 보드** | **전체 칸** | **플레이어** | **색 블록 총수** | **색상별 개수** |
|---|---|---|---|---|
| 7×7 | 49 | 1 | 48 | 12 |

## 2.2 셀(Cell) 상태

| **상태** | **설명** | **필수 데이터** |
|---|---|---|
| Player | 플레이어가 현재 점유한 칸 | 좌표, 선택한 캐릭터의 외형 |
| ColorBlock | 4가지 색 중 하나를 가진 일반 블록 | ColorID |
| Empty | 블록 제거 후 남는 빈칸을 사용할 경우 (MVP에서는 생성되지 않음) | 별도 색 없음 |
| Growing | 블럭 제거 후 생성되는 중인 경우 | 생성까지 남은 시간, 전체 생성 시간, 생성될 색(화면에는 숨김) |

**권장 데이터 표현:** 2차원 배열 Grid[y][x]에 셀 상태를 저장하고, 플레이어 위치는 별도 playerPos로 캐시한다. 화면 오브젝트 위치가 아니라 “그리드 데이터”를 진실의 원천(Source of Truth)으로 둔다.

## 2.3 초기 보드 생성 알고리즘

1. N×N 그리드를 생성하고 중앙 좌표를 Player로 예약한다.

2. 각 색의 ColorID를 정확히 (N²-1)/4개씩 리스트에 넣는다.

3. 리스트를 seed 기반 RNG로 셔플한다(Fisher-Yates).

4. 중앙을 제외한 모든 칸에 순서대로 색 블록을 배치한다.

5. 초기 매치 형태는 검사하지 않는다 (이동 전에는 판정하지 않으므로, A8).

# 3. 플레이어 이동과 교환(Swap) 규칙

## 3.1 1회 이동의 정확한 처리 순서

| **순서** | **단계** | **처리** |
|---|---|---|
| 1 | Input | 방향 입력을 1개 결정한다. 같은 프레임에 여러 입력이 오면 마지막 1개. |
| 2 | Validate | 목표 좌표가 보드 내부인지, 현재 이동 가능한 상태(PLAYING, 0초 전)인지 확인한다. 이동 중이면 버퍼에 1개 저장. |
| 3 | Move / Swap | 목표가 색 블록·Growing이면 서로 위치 교환(Growing은 남은 시간·예정 색 유지). 목표가 Empty면 플레이어만 이동하고 이전 칸이 Empty가 된다. |
| 4 | Commit | 그리드 데이터와 플레이어 좌표를 먼저 확정한다. |
| 5 | Move Time | 이동 애니메이션 시간(0.12초)이 지날 때까지 새 이동을 시작하지 않는다. |
| 6 | Resolve Match | 새 플레이어 위치 기준 상·하·좌·우 4칸을 검사한다. |
| 7 | Clear & Score | 조건 충족 시 4블록을 Growing으로 바꾸고 +2.5초, 제거한 색으로 족보·캐릭터 능력 조건을 진행한다. |
| 8 | Feedback | 이동/제거 애니메이션, 효과음, 점수 팝업을 재생한다 (로직은 연출을 기다리지 않는다). |
| 9 | Unlock | 버퍼에 입력이 있으면 바로 실행, 없으면 다음 입력을 받는다. |

# 4. 매치 판정과 블록 제거

## 4.1 매치 조건

**Match =** 플레이어 기준 상·하·좌·우 네 좌표가 모두 보드 내부에 존재하고, 네 칸이 모두 ColorBlock이며, ColorID가 동일한 경우.

> **판정식** Up == Down == Left == Right 이면서 네 셀이 모두 ColorBlock이면 MatchSuccess = true. 대각선은 판정에 포함하지 않습니다. Growing·Empty·플레이어가 하나라도 끼면 실패입니다.

## 4.2 제거 후 보드 처리 — 가장 중요한 설계 선택

| **방식** | **게임에 미치는 영향** | **장점** | **주의점** |
|---|---|---|---|
| 지연 랜덤 리필 (확정) | 제거 후 일정 시간 지난 뒤 같은 위치에 새 블록 생성 | 밀도 유지 가능, 반복 플레이 안정적 | 운 영향 증가 → 리필 직후 자동 매치는 판정하지 않음 |

## 4.3 지연 랜덤 리필 규칙

- 매치된 4칸은 Growing이 된다. 생성될 색은 이때 seed RNG로 4색 중 균등하게 정한다 (B4). 화면에는 다음 색을 보여주지 않는다.

- 리필 시간 = `max(1.0초, 2.5초 / 배속)`. Growing이 시작될 때 한 번 계산한다 (D2).

- 플레이어는 Growing 칸으로 이동할 수 있다. 교환 시 Growing은 남은 시간·예정 색을 유지한 채 플레이어가 있던 칸으로 옮겨진다 (B2).

- 색 블록은 플레이어와 교환될 때만 이동한다. 자체적으로 빈칸으로 떨어지거나 미끄러지지 않는다.

- 리필로 매치 형태가 생겨도 판정하지 않는다. 다음 이동의 결과로만 득점한다 (C3).

- Growing의 진행도는 칸 중앙에서 바깥으로 차오르는 사각형으로 표시한다.

- 논리적으로 더 이상 매치가 불가능한 상태(dead board)를 감지하지 않는다.

- 블럭을 제거하면 +2.5초를 얻는다 (상한 없음, B11).

| 기본 추가 시간 | 블럭 제거 시 시간 추가 | +2.5초, 상한 없음 (B11) |
| 0초 입력 | 입력 금지 | 0 이하가 되는 순간 신규 입력 금지, 버퍼 폐기 |
| 진행 중 이동 | 0초 전까지 가능 | 0초 전에 승인된 이동은 판정까지 완료, 그 점수 인정, 시간 보너스로 재개되지 않음 (D6) |
| 결과 화면 | 최종 점수, 최고 점수, 재시작, 메인메뉴 | 최종 점수, 최고 점수(NEW BEST 표시), 재시작, 메인 메뉴 (A4) |
| 최고 점수 | 로컬 저장 필수, 온라인 저장 선택 | 로컬 저장 (B15). 일시정지에서 메뉴로 나간 판은 반영하지 않음 |

> 참고: 매치 없이 가만히 있으면 가속 때문에 실제 시간 약 48.3초 뒤 0초가 된다 (∫(1+0.01t)dt = 60).

## 5.1 족보 시스템

- 맵 위에 족보 3개가 보인다. 왼쪽부터 2칸, 3칸, 4칸이며 완성 점수는 200 / 600 / 1000점이다.

- 족보의 색은 4가지 색 중 랜덤이며 중복을 허용한다 (B10).

- 매치 1회 = 족보 1칸 (B8). 다음에 필요한 색을 제거하면 한 칸 진행하고, 다른 색을 제거하면 무시한다(진행이 초기화되지 않음, B6).

- 세 족보는 각자 독립적으로 진행한다. 한 번의 제거로 여러 족보가 진행될 수 있고, 동시에 완성되면 점수를 합산한다 (B7).

- 완성된 족보는 사라지고 같은 자리에 같은 길이의 새 족보가 나타난다 (B10).

- 표시: 족보 박스 전체 배경은 다음에 제거해야 하는 색. 칸마다 색과 문양을 보여주고, 제거한 칸은 흐리게, 다음 칸은 흰 테두리로 강조한다 (D9).

- Time Bonus: 블럭 제거 시 +2.5초.

## 5.2 캐릭터와 능력

플레이어는 캐릭터 선택 창에서 캐릭터를 고른다. 캐릭터마다 플레이어 블록 외형(채움·테두리 색)이 다르고, 능력이 있는 캐릭터는 **능력 발동 조건**(족보처럼 제거할 색 순서)을 완성하면 능력이 발동한다.

**공통 규칙**

- 조건 진행 규칙은 족보와 같다: 다음 색이면 한 칸 진행, 다른 색은 무시(진행 유지). 조건 자체로는 점수를 주지 않는다.

- 발동하면 진행이 0으로 돌아가며 반복 발동할 수 있다.

- 능력 조건은 HUD에서 4칸 족보 오른쪽에 흰 테두리 박스로 표시한다(박스 4개가 한 줄에 들어가도록 족보 칸 크기를 줄인다).

- 지속 효과·대기 효과는 HUD 왼쪽 위에 표시한다(STOP 4.7 / FEVER 9.2 / ALL IN / WILD).

| **캐릭터** | **발동 조건** | **능력** | **세부 규칙** |
|---|---|---|---|
| 기본 | 없음 | 아무 능력 없음 | 족보 3개만 표시 |
| 정원사 | 노랑 → 빨강 | 촉진: 판 위에 모든 자라는 중인 블럭이 다 자람 | 방금 매치한 4칸 포함. 완성 후 자동 판정 없음 |
| 시계공 | 파랑 → 초록 → 파랑 | 정지: 5초 동안 시간이 줄지 않음 | 게임 시계 정지 → 남은 시간·배속 고정. 리필·이동은 계속. 정지 중 재발동 시 남은 정지 시간에 +5초 |
| 도박사 | 빨강 → 빨강 | 올인: 다음에 완성하는 족보 점수 X3 | 발동시킨 매치에는 미적용. 동시 완성이면 합계 ×3 |
| 축제꾼 | 초록 → 노랑 → 파랑 | 피버: 10초동안 공개 족보가 한칸 짜리로 바뀜, 끝나면 원래 족보가 진행도 그대로 복귀 | 1칸 족보는 무작위 색, 슬롯 점수 그대로. 피버 중 매치는 원래 족보에 반영 안 됨. 재발동 시 +10초 |
| 연금술사 | 파랑 → 노랑 → 파랑 | 변성: 가장 많이 진행한 족보가 다음에 원하는 색으로 판의 블럭 4개를 바꿈 | 동률이면 남은 칸이 적은 족보 → 앞 슬롯. 그 색이 아닌 색 블록 4개를 무작위로. 자동 판정 없음 |
| 조커 | 노랑 → 빨강 → 파랑 → 초록 | 와일드: 다음 클리어 1회가 색과 무관하게 모든 족보를 한 칸 진행 | 발동 다음 매치 1회에 적용 |

# 6. 게임 상태(State)와 전환

| **State** | **설명** | **입력 가능 여부** |
|---|---|---|
| Title / Menu | 메인 메뉴(START / CHARACTER / OPTIONS), 캐릭터 선택, 옵션 | 메뉴 입력 |
| Ready | 보드 생성 및 READY → GO 연출 (타이머·가속·리필 정지) | 이동 입력 불가 |
| Playing | 게임 진행. 0초 이후 승인된 이동의 판정 대기도 포함 | 이동 입력 가능 (0초 이후 불가) |
| Paused | 타이머·가속·리필·능력 타이머 정지, 보드 가림. Playing에서만 진입 | 퍼즐 입력 불가 (재개 / 메뉴로 나가기) |
| GameOver | TIME UP 표시 1.0초 | 퍼즐 입력 불가 |
| Result | 점수/최고 점수/재시작/메인 메뉴 | 메뉴 입력 |
| Abandoned | 일시정지에서 메뉴로 나감. 종료 상태, 점수 미반영 | 없음 |

> **구현 팁** 상태를 bool 여러 개(isMoving, isPaused, isGameOver…)로 흩어놓기보다 GameState Enum과 명시적 상태 전환으로 관리하면 입력 충돌과 종료 버그를 줄일 수 있습니다. (구현: READY → PLAYING ⇄ PAUSED, PLAYING → GAME_OVER → RESULT → Retry → READY, PAUSED → ABANDONED)

# 7. UI/UX와 피드백

## 7.1 플레이 화면 필수 HUD

- 남은 시간: 화면 위쪽 가운데에 초 단위(소수 1자리)와 현재 배속 표시(예: `42.3  x1.18`). 마지막 10초는 빨간색 + 매 초 강조, 시계공 정지 중에는 하늘색.

- 현재 점수: 획득 즉시 변화가 보이게 표시. 족보 완성 시 “+N”, 능력 발동 시 “촉진!” 등의 문구가 떠올랐다 사라진다.

- 조작 안내: 옵션 조작 탭에서 방법 설명.

- 일시정지 버튼: 화면 오른쪽 위. ESC·Android 뒤로 가기도 동일.

- 최고 점수: 결과 화면에만 표시

- 족보: 맵 상단에 2칸, 3칸, 4칸 족보 (+ 능력 조건 박스)

- 능력 상태: 화면 왼쪽 위 (STOP / FEVER 남은 시간, ALL IN / WILD 대기)

- 화면 비율이 달라도(세로로 긴 폰, 태블릿) HUD·보드·가상 방향키가 겹치지 않고, 노치·펀치홀 영역을 피한다.

## 7.2 플레이 피드백

| **상황** | **권장 피드백** | **목적** |
|---|---|---|
| 정상 이동 | 짧은 이동 애니메이션(0.12초) + 가벼운 SFX | 입력 응답성 전달 |
| 블록 교환 | 밀려나는 블록이 잠깐 작아지고 플레이어는 위에 그려져 통과하지 않는 교환이 보이도록 | 규칙 학습 |
| 매치 성공 | 4블록 동시 강조(커졌다 돌아옴) → Growing 표시 | 보상감 |
| 족보 완성 | 족보 박스 강조 + “+N” 팝업 | 보상감 |
| 능력 발동 | 능력 박스 강조 + “능력 이름!” 팝업 | 보상감 |
| 벽 입력 | 작은 흔들림 | 무효 입력 인지 |
| 10초 이하 | 타이머 빨간색 + 매 초 강조, 틱 사운드 자리 | 긴장감 |
| 종료 | 입력 즉시 잠금 + TIME UP → 결과 화면 | 혼란 방지 |

> 사운드: 이벤트별 효과음 자리(이동, 교환, 벽, 매치, 리필, 족보 완성, 능력, GO, 틱, TIME UP)만 있고 실제 음원은 아직 없다. 오디오 버스는 Master ← SFX(효과음), BGM(배경음, 미사용)이며, 서로 다른 효과음은 같은 순간에 나도 끊기지 않는다. 옵션의 오디오 탭은 Master 버스 볼륨(마스터 볼륨)을 조절한다.

## 7.3 색상 접근성

- 색만으로 구분하지 않고 블록마다 문양을 추가한다: 빨강 원 · 노랑 삼각형 · 파랑 사각형 · 초록 마름모 (블록과 족보 칸 모두).

- 4색은 명도 차이까지 확보해 색각 이상 사용자도 구분 가능하도록 테스트한다.

- 플레이어 블록은 네 색 블록과 절대 혼동되지 않는 형태/테두리/애니메이션을 사용한다 (어두운 채움 + 캐릭터별 테두리 색).

- 색상 테마를 데이터로 분리하면 이후 접근성 팔레트나 스킨을 쉽게 추가할 수 있다.

# 8. 메뉴와 옵션

| **화면** | **구성** |
|---|---|
| 메인 메뉴 | START, CHARACTER, OPTIONS 버튼, 현재 선택된 캐릭터 이름 |

| 옵션 - 오디오 | **마스터 볼륨** 0~100 (기본 100) 슬라이더. 모든 소리(효과음·배경음)에 적용, 0이면 음소거. 움직이는 동안 바로 반영, 손을 떼거나 화면을 나갈 때 저장 |
| 옵션 - 계정 | 준비 중 |

- 조작 방법이 스와이프면 가상 방향키를 숨기고, 가상 방향키면 스와이프를 받지 않는다.

- 저장 항목(로컬): 최고 점수, 선택한 캐릭터, 조작 방법, 마스터 볼륨.

# 9. 예외 상황(Edge Cases) 명세

| **상황** | **처리 규칙** |
|---|---|
| 벽 바깥으로 이동 입력 | 이동하지 않음. 매치 재판정도 하지 않음. 입력 잠금 없음. |
| 플레이어가 가장자리/모서리에 위치 | 4방향이 모두 존재하지 않으므로 매치 불가. |
| 목표 칸이 ColorBlock | Player와 해당 블록의 셀을 교환. |
| 목표 칸이 Growing | 교환. Growing은 남은 시간·예정 색을 유지한 채 이동. |
| 목표 칸이 Empty | Player만 이동, 이전 Player 칸은 Empty. (MVP에서는 발생하지 않음) |
| 이동 전 이미 주변 4색 동일 | 이동 전에는 점수 없음. 다음 유효 이동 결과가 다시 조건을 만들 때만 득점. |
| 한 프레임에 두 방향 입력 | 마지막 입력 1개만 처리. |
| 이동 애니메이션 중 추가 입력 | 1개 버퍼(덮어쓰기), 판정 후 실행. |
| 제거 연출 중 추가 입력 | 이동 가능 (연출은 화면 효과일 뿐, D7). |
| 타이머가 0이 되는 순간 입력 발생 | 시간 종료 판정을 우선하여 신규 이동 거절. |
| 0초 직전 이미 이동 승인 | 판정까지 마친 뒤 최종 점수 확정. 시간 보너스로 재개되지 않음. |
| 한 프레임 안에 판정·리필·0초가 겹침 | 실제 일어난 시각 순서대로 처리 (프레임레이트와 무관). |
| 기기가 순간적으로 멈춤(로딩 등) | 한 프레임에 반영하는 시간은 최대 0.25초. |
| Pause 중 | 타이머·가속·리필·능력 타이머와 퍼즐 입력 모두 정지. 공정성을 위해 보드를 가린다. |
| 창 포커스 잃음 / 앱 백그라운드 | 자동 Pause. |
| Pause 중 메뉴로 나가기 | 판 종료(Abandoned), 점수 미반영. |
| 초기 생성 직후 정답 형태 존재 | 이동 전 판정하지 않음. |
| 남은 색 블록이 4개 미만 | 지연 리필 방식이므로 판정하지 않음. |
| 리필 직후 자동 정답 생성 | 리필 직후 플레이어 입력 없이 점수 생성 불가. |
| 능력으로 블록이 바뀌거나 즉시 자람 | 자동 판정하지 않음. 다음 이동의 결과로만 득점. |
| 설정 값이 잘못됨(짝수 보드 등) | 오류를 기록하고 기본 설정으로 진행. |

# 11. 관련 용어 정리(우리끼리의 명칭 통일)

| **용어** | **의미** |
|---|---|
| Grid / Board | 칸으로 나뉜 퍼즐 전체 공간. |
| Cell / Tile | 그리드의 한 칸. “타일”이 시각 요소를 뜻할 수도 있으므로 코드에서는 Cell과 View를 구분하면 좋음. |
| Growing | 제거된 칸이 새 블록으로 자라는 중인 상태. |
| 족보 (Recipe) | 제거할 색 순서. 완성하면 점수. |
| 능력 발동 조건 | 캐릭터 능력을 발동시키는 색 순서. 족보와 같은 규칙으로 진행. |
| 배속 (Time Rate) | 남은 시간이 줄어드는 속도. 1 + 0.01 × 경과 시간. |
| Orthogonal / 4-neighbor | 대각선을 제외한 상·하·좌·우 인접 관계. |
| Adjacency | 두 셀이 서로 인접해 있는 관계. |
| Swap | 두 셀/오브젝트의 위치를 서로 교환하는 처리. |
| Match | 정해진 조건을 만족해 제거/득점 가능한 상태. 이 게임에서는 플레이어 주변 십자 4칸 동일색. |
| Clear / Remove | 매치된 블록을 보드에서 제거하는 처리. |
| Resolve | 이동 이후 발생하는 판정, 제거, 점수 반영을 순서대로 처리하는 단계. |
| Resolution Order | 동시에 발생할 수 있는 이벤트의 처리 우선순위. |
| RNG | Random Number Generator. 초기 배치를 무작위화하는 난수 시스템. |
| Seed | 같은 난수 결과를 재현하기 위한 초기값. |
| Deterministic | 동일 입력/seed에서 항상 동일 결과가 나오는 성질. |
| Input Buffer | 애니메이션 등으로 즉시 실행할 수 없는 입력을 잠시 저장했다가 다음에 실행하는 방식. |
| Cooldown | 연속 행동 사이에 강제로 두는 최소 간격. |
| DAS / Repeat Delay | 키를 누르고 있을 때 자동 반복이 시작되기 전 지연. 그리드 게임 조작감에 중요. |
| Game Loop | 플레이어가 반복하는 핵심 행동 순환. |
| State Machine | Ready/Playing/Paused/GameOver처럼 게임 상태와 전환을 명시적으로 관리하는 구조. |
| HUD | 플레이 중 항상 보이는 점수/시간 등 정보 UI. |
| Feedback | 입력과 결과를 애니메이션, 사운드, 진동, 숫자 등으로 알려주는 반응. |
| Edge Case | 일반 흐름이 아닌 경계/동시입력/0초 등의 예외 상황. |
| Softlock | 게임은 종료되지 않았지만 사실상 목표 진행이 불가능해지는 상태. |
| Dead Board | 더 이상 유효한 매치가 생성되기 어려운/불가능한 보드 상태. |
| Cascade | 제거 후 낙하/리필 때문에 추가 매치가 연쇄적으로 발생하는 현상. (이 게임에는 없음) |
| MVP | 핵심 재미를 검증하기 위한 최소 기능 제품/빌드. |
| Acceptance Criteria | 기능이 “완료”되었다고 판단할 수 있는 구체적 검수 조건. |
| Source of Truth | 여러 표현 중 실제 게임 상태를 결정하는 기준 데이터. 이 게임에서는 논리 Grid가 적합. |

# 12. 개발 완료 판정용 QA 체크리스트

| **테스트 항목** | **Acceptance Criteria** |
|---|---|
| 보드 생성 | 정해진 N×N 크기로 생성되고 Player가 정확히 중앙에 위치한다. |

| 교환 | 색 블록으로 이동할 때 두 위치가 정확히 교환된다. |
| 경계 | 보드 밖으로 나가지 않는다. |

| 프레임 독립성 | 30/60/120fps에서 이동/타이머 규칙이 동일하다. |
| 저장 | 최고점·캐릭터·조작 방법·마스터 볼륨이 재실행 후 정상 유지된다. |

# 13. MVP 기준 권장 Proposal….(초기 프로토타입용) — 구현 현황

| **항목** | **MVP 값 (구현됨)** |
|---|---|
| 보드 | 7×7 |
| 색 | 4색, 각 색 동일 개수, 색별 문양 |
| 시작 | Player 중앙, READY → GO 후 60초 시작 |
| 입력 | 키보드(방향키·WASD) + 스와이프 또는 가상 방향키(옵션), 1회 1칸, 벽 입력 무효 |

| 성공 | 네 칸 모두 존재 + ColorBlock + 동일 ColorID |
| 제거 | 4블록 Growing으로 변경, +2.5초 |
| 보충 | 리필 시간(2.5초 / 배속, 최소 1초) 후 생성 |
| 점수 | 족보 완성 시 족보에 해당하는 점수 부여 (200/600/1000) |

| 입력 잠금 | 이동 중 입력 1개 버퍼 |
| 종료 | 0초에서 신규 입력 차단, 승인된 resolve 완료 후 Result |
| 결과 | Final Score + Best + Retry + Main Menu |

> **프로토타입의 첫 검증 질문**
>
> “지연 리필 + 시간 가속 + 족보 구조가 한 판 동안 점점 더 흥미로운가, 아니면 시간 보너스·캐릭터 능력으로 판이 늘어지거나 점수가 폭주하는가?”를 가장 먼저 확인해봐야 함. 이 답을 위해 10.1장 지표 기록 기능이 필요.
